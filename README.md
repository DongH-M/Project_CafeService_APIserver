# 비 오는 날 디저트 준비량 예측 API

카페 사장님이 **날짜**(내일 ~ 3일 뒤)를 넣으면, 기상청 단기예보의 **예상 강수량**과 **요일**로 그날의 **디저트 예상 판매량**과 **적정 재고량**을 알려 주는 FastAPI 서버입니다.
인증키가 없어도 `data/sample` 폴더의 샘플 예보(CSV)로 바로 실행됩니다. 로그인은 필요 없습니다.

## 예측 방법
2024-01-01 ~ 2025-12-31 서울 카페 판매량과 기상청 일강수량(727일)으로 만든 회귀식입니다.

```
예상판매량 = 요일별 기준값 − 0.322178 × 예상 일강수량(mm)  을 반올림   → n개
적정재고량 = 예상판매량(반올림한 값) + 8                              → m개
```

| 요일 | 월 | 화 | 수 | 목 | 금 | 토 | 일 |
|---|---|---|---|---|---|---|---|
| 기준값(비 0mm) | 74.9615 | 74.8720 | 75.8384 | 76.9225 | 74.4141 | 92.3010 | 96.6299 |

- 예) 월요일, 10mm → 74.9615 − 0.322178 × 10 = 71.74 → 반올림 **예상 판매량 72개**, 72 + 8 → **적정재고량 80개**
- +8개: 2024년으로 학습하고 2025년으로 검증했을 때의 평균절대오차(MAE 7.98개)
- 예상 일강수량 = 그날 1시간 강수량(PCP) 예보 24개의 합. 24시간 예보가 다 있는 날만 계산합니다.
- PCP 변환: 기상청이 숫자로 준 값(예: `2.0mm`, `6.0mm`, `0`)은 **숫자 그대로** 씁니다. 숫자가 아닌 아래 값만 바꿉니다.
  - 강수없음 → 0
  - 1mm 미만 → 0.5
  - 30.0~50.0mm (구간) → 40 (구간 가운데 값)
  - 50.0mm 이상 → 50
- 모델 검증: 2025년 10~12월(91일)에서 회귀모델 MAE 7.64개 < 요일별 평균 기준모델 MAE 8.05개 (평가 기간을 뺀 2024-01 ~ 2025-09로 학습)

## 1. 설치
Python 3.10 이상이 필요합니다.

저장소를 내려받고 폴더로 이동합니다. (Git이 없으면 GitHub 페이지의 **Code → Download ZIP**으로 받아 압축을 풀어도 됩니다)
```powershell
git clone https://github.com/DongH-M/Project_CafeService_APIserver.git
```
```powershell
cd Project_CafeService_APIserver
```

필요한 패키지를 설치합니다. 이후 명령은 모두 이 폴더(README.md가 있는 곳)에서 실행합니다.
```powershell
pip install -r requirements.txt
```
(macOS는 `pip3`, `python3`)

## 2. 실행 (인증키 없이 = 샘플 모드)
```powershell
python -m uvicorn main:app --reload
```
브라우저에서 아래 주소를 엽니다.
- http://127.0.0.1:8000/docs : 주소별 **Try it out → Execute**로 실행
- 또는 주소창에 직접 입력: http://127.0.0.1:8000/status

`/status`는 지금 모드와 입력 가능한 날짜(내일 ~ 3일 뒤)를 알려 줍니다.
```json
{"mode": "sample", "rain_source": "샘플 데이터(data/sample)", "predict_dates": ["2026-11-26", "2026-11-27", "2026-11-28"], ...}
```

## 3. 인증키로 실제 예보 쓰기 (선택)
1. [공공데이터포털](https://www.data.go.kr)에서 「기상청_단기예보 조회서비스」를 활용신청하고 **Decoding 키**를 확인합니다.
2. `.env.example`을 복사해 `.env`를 만듭니다.
   ```powershell
   Copy-Item .env.example .env
   ```
3. `.env`를 열어(`notepad .env`) `여기에_Decoding_키` 자리에 내 키를 넣고 저장합니다.
4. 서버를 껐다가(Ctrl+C) 다시 켜고 `/status`가 `"mode": "api"`인지 확인합니다.

> **인증키 주의**
> - 키는 `.env`에만 둡니다. 코드, README, 카카오톡, 캡처에 넣지 않습니다.
> - `.env`는 `.gitignore`에 등록되어 있어 Git에 올라가지 않습니다. 커밋 전에 `git status`로 `.env`가 목록에 **없는지** 꼭 확인합니다.

### 샘플 데이터 (`data/sample/forecast_sample.csv`)
| 열 | 뜻 |
|---|---|
| `day_offset` | 오늘 기준 며칠 뒤 (1 = 내일, 2 = 모레, 3 = 글피) |
| `fcst_time` | 예보 시각 (0000 ~ 2300) |

날짜 대신 "며칠 뒤"로 저장되어 있어서 언제 실행해도 내일 ~ 3일 뒤 날짜로 동작합니다.
들어 있는 값은 **2026-11-25 17시 발표 실제 기상청 예보**(서울)입니다. 내일 0mm, 모레 1.5mm, 글피 0mm.
키가 있으면 아래 명령으로 최신 예보로 다시 저장할 수 있습니다. 키와 요청 URL은 저장되지 않습니다.
```powershell
python make_sample.py
```

## 4. 주소
| 주소 | 설명 | 예시 |
|---|---|---|
| `GET /predict` | 예상 판매량, 적정 재고량, 안내 문구 | `/predict?date=2026-11-27&usual_qty=70` |
| `GET /status` | 모드(api/sample)와 입력 가능한 날짜 | `/status` |
| `GET /history` | 과거 기록 목록. `weekday`(월요일~일요일), `max_rain`(0~300) 조건 | `/history?weekday=토요일&max_rain=0` |
| `GET /history/{날짜}` | 날짜 하나의 기록 | `/history/2024-07-18` |

### `/predict` 입력
| 이름 | 필수 | 설명 |
|---|---|---|
| `date` | 필수 | 디저트 준비량을 알고 싶은 날짜 `YYYY-MM-DD`, 내일 ~ 3일 뒤. 요일은 자동 계산 |
| `usual_qty` | 선택 | 평소 준비 수량(개). 비우거나 음수면 입력하지 않은 것으로 처리 |

### `/predict` 출력 예시 (2026-11-25에 실행, 모레 = 금요일 1.5mm)
`/predict?date=2026-11-27&usual_qty=70`
```json
{
  "date": "2026-11-27", "weekday": "금요일", "rain_mm": 1.5,
  "predicted_sales": 74, "recommended_stock": 82, "usual_qty": 70, "diff": 12,
  "summary": "예상 판매량 : 74 , 적정 재고량 : 82 , 평소 준비량 : 70",
  "lines": ["2026년 11월 27일 금요일", "디저트 74개 판매 예상", "12개 더 준비하세요!", "총 82개 준비하세요"],
  ...
}
```
| 평소 준비량 k | 셋째 줄 문구 |
|---|---|
| 입력 안 함 / 음수 | 생략 |
| k < 적정재고량 m | `m−k개 더 준비하세요!` |
| k > m | `k−m개 줄이세요!` |
| k = m | `평소대로 준비하세요!` |

## 5. 오류 안내
| 상황 | 코드 | 문구 |
|---|---|---|
| 날짜가 내일 ~ 3일 뒤가 아님 (오늘 포함) | 400 | 당일 기준으로 +3일내의 날짜를 입력하시오 |
| 그날 예보가 없거나 24시간이 안 됨 | 400 / 404 | 데이터가 부족해 강수량을 예측 할 수 없습니다. 나중에 다시 시도해주세요. |
| 날짜·숫자 형식이 틀림 (`date=abc`, `usual_qty=abc`) | 422 | FastAPI 기본 안내 |
| 기상청 API 오류 (키 미등록, 연결 실패) | 502 | 원인 코드 안내 (키·URL은 표시하지 않음) |
| 샘플 파일이 없음 | 503 | 샘플 파일이 없습니다 |
| 기록 없는 날짜 (`/history/2024-02-10`) | 404 | 기록이 없습니다 |

오류가 나도 서버는 계속 켜져 있고 다음 요청에 응답합니다. 결과가 0건이면 `{"count": 0, "items": []}`로 답합니다.

## 6. 만들면서 발견한 문제와 수정 과정

### 요건정의서와 비교해서 고친 것
처음 만든 API를 요건정의서와 한 줄씩 대조해 다른 점을 찾고 고쳤습니다.

| 발견한 문제 | 요건정의서 | 수정 |
|---|---|---|
| 강수량(`rain_mm`)을 선택 입력으로 받고 있었음 | 강수량은 입력이 아니라 API로 가져옴 | `rain_mm` 입력을 삭제. 항상 예보(키가 없으면 샘플)에서 가져옴 |
| 평소 준비 수량 입력이 없었음 | [선택] 평소 준비 수량(개) | `usual_qty` 추가. 비우거나 음수면 입력하지 않은 것으로 처리 |
| 적정재고량 계산 순서가 정해져 있지 않았음 ("반올림 후 +8"과 "+8 후 올림"은 계산값 71.30일 때 79개 대 80개로 달라짐) | 예상판매량을 **반올림**하고, 그 값에 **+8** | 요건정의서를 확정하고 "반올림한 예상판매량 + 8"로 통일 |
| 출력 문구가 한 줄("예상 판매량 약 n개, 적정재고량 m개")뿐이었음 | 날짜·요일, n개 판매 예상, 더 준비/줄이세요/평소대로, 총 m개 | `summary`, `lines`로 요건 문구 그대로 출력. 오류 문구도 요건대로 변경 |
| 허용 날짜가 모드마다 달랐음 (샘플 모드는 샘플 파일의 고정 날짜) | 당일 기준 +3일 | 키가 있든 없든 내일 ~ 3일 뒤로 통일 |
| 샘플 데이터가 JSON 형식이었음 | data/sample **CSV** | `forecast_sample.csv`로 변경 |

- 그래프는 이 API 서버의 역할이 아니어서 만들지 않았습니다. 대신 화면에서 그래프에 쓸 수 있도록 `/history`를 남겨 두었습니다.
- `/status`도 실행 모드와 입력 가능한 날짜를 확인하는 용도로 남겨 두었습니다.

### 코드에서 발견한 버그
| 증상 | 원인 | 해결 |
|---|---|---|
| 오늘 날짜의 예상 강수량이 실제보다 적게 나옴 | 단기예보에는 이미 지난 시간이 없어서, 남은 시간의 예보만 더해짐 | 24시간 예보가 다 있는 날만 계산하고, 날짜를 내일 ~ 3일 뒤로 제한 |
| 잘못된 키로 호출하면 원인이 "알 수 없는 응답"으로만 나옴 | 기상청 오류 본문이 XML이 아니라 JSON으로 와서 읽지 못함 | JSON·XML 둘 다 읽도록 고침 → `SERVICE_KEY_IS_NOT_REGISTERED_ERROR (코드 30)` 표시 |
| 샘플 날짜가 지나면 키 없이 예측이 안 됨 | 샘플을 고정 날짜(2026-11-26 ~ 28)로 저장함 | "오늘 기준 며칠 뒤(`day_offset`)"로 저장해 언제 실행해도 내일 ~ 3일 뒤로 동작 |
| '키 없음' 테스트가 실제 키로 실행됨 | 서버가 켜질 때 `.env`를 자동으로 읽음 | 테스트 안에서만 환경변수를 지워 확인 (`.env` 파일은 그대로) |

## 7. 한계
**예측 범위**
- 단기예보는 3일 뒤(글피)까지만 있어서 그보다 먼 날은 예측할 수 없습니다. 오늘은 지난 시간의 예보가 없어 제외합니다.
- 발표 시각에 따라 3일 뒤 예보가 24시간이 안 되면 "데이터가 부족해…" 안내가 나옵니다.

**모델**
- 요일과 강수량 두 가지만 씁니다. 판매량 변동의 약 49%만 설명합니다(R² 0.489). 기온, 공휴일, 행사, 신메뉴, 계절 같은 요인은 반영하지 않습니다.
- 카페 1곳, 2년(727일) 데이터로 만든 식이라 다른 매장이나 지역에 그대로 쓰기 어렵습니다.
- 계수는 코드에 고정되어 있습니다. 새 판매 데이터가 쌓여도 자동으로 다시 학습하지 않습니다.
- 비가 아주 많이 오면 계산값이 음수가 될 수 있어 0으로 고정합니다. 이렇게 큰 비는 학습 데이터에 거의 없어 정확도가 낮습니다.

**강수량**
- 예보 자체에 오차가 있습니다. 예보가 틀리면 판매량 예측도 같이 틀립니다.
- 기상청 예보는 대부분 숫자(예: 2.0mm)로 와서 그대로 쓰지만, "1mm 미만", "30.0~50.0mm", "50.0mm 이상"처럼 숫자 하나로 정해지지 않는 값은 각각 0.5mm, 구간 가운데 값(40mm), 50mm로 가정해 계산합니다. 이 경우 실제 강수량과 차이가 날 수 있습니다.
- 서울 격자 한 곳(nx=60, ny=127)의 예보만 씁니다.

**적정재고량**
- +8개는 평균 오차만큼의 여유입니다. 2024년으로 학습하고 2025년으로 검증했을 때 실제 판매량이 "예상 + 8"을 넘은 날이 약 17%였습니다. 즉 +8개로도 대략 6일에 1번은 품절이 날 수 있습니다.

**샘플 모드**
- 인증키가 없으면 저장해 둔 예보(2026-11-25 17시 발표)를 실행한 날 기준 내일 ~ 3일 뒤에 그대로 붙여 계산합니다. 실제 그날의 날씨가 아니라 실행 확인용입니다.
